Git y GitHub, paso a paso

Aprende a guardar la historia de tu código, trabajar en ramas y colaborar con otras personas. Cada sección es un commit en el camino.

Git es el programa que corre en tu computadora y registra los cambios de tus archivos.
GitHub es un sitio web que guarda tus repositorios en línea y facilita colaborar.

Instalar y configurar

Descarga Git desde git-scm.com y comprueba la instalación:

git --version

Antes de tu primer commit, dile a Git quién eres. Este nombre aparecerá en cada cambio que guardes.

git config --global user.name "Tu Nombre"
git config --global user.email "tu@correo.com"
git config --global init.defaultBranch main

Flujo básico

Un archivo pasa por tres zonas: tu carpeta de trabajo, el área de preparación (staging) y el repositorio.

Carpeta de trabajoeditas archivos
git add
Stagingeliges qué guardar
git commit
Repositorioqueda en la historia
git init                      # crea un repositorio nuevo
git status                    # ve qué cambió
git add archivo.txt           # prepara un archivo
git add .                     # prepara todo
git commit -m "Agrega la página de inicio"
git log --oneline --graph     # revisa la historia

Un buen mensaje de commit dice qué cambió y por qué, en pocas palabras y en presente: "Corrige el cálculo del total".

Ramas

Una rama es una línea de trabajo independiente. Te permite probar ideas sin tocar la versión estable (main).

git branch                    # lista las ramas
git switch -c nueva-funcion   # crea y cambia a una rama
git switch main               # vuelve a main
git branch -d nueva-funcion   # borra una rama ya fusionada

Fusionar y conflictos

Cuando termines en tu rama, fusiónala con main:

git switch main
git merge nueva-funcion

Si dos ramas cambian las mismas líneas, Git te pedirá resolver un conflicto. Abre el archivo y verás marcas como estas:

<<<<<<< HEAD
titulo = "Versión de main"
=======
titulo = "Versión de tu rama"
>>>>>>> nueva-funcion
  1. Deja solo el texto final que quieres y borra las marcas.
  2. Ejecuta git add archivo.
  3. Termina con git commit.

Conectar con GitHub

  1. Crea una cuenta en github.com y un repositorio nuevo vacío.
  2. Copia la URL del repositorio (HTTPS o SSH).
  3. Conéctalo y sube tu trabajo:
git remote add origin https://github.com/usuario/mi-repo.git
git push -u origin main

Para traer un repositorio que ya existe, o actualizar el tuyo:

git clone https://github.com/usuario/mi-repo.git
git pull                      # descarga y fusiona cambios remotos
git fetch                     # descarga sin fusionar

GitHub ya no acepta contraseñas en la terminal. Usa una clave SSH o un token de acceso personal, o instala GitHub CLI y ejecuta gh auth login.

Pull requests

Un pull request (PR) es una propuesta para fusionar tu rama en otra. Sirve para que el equipo revise el código antes de integrarlo.

  1. Crea una rama y haz tus commits.
  2. Súbela: git push -u origin nueva-funcion.
  3. En GitHub, pulsa Compare & pull request y describe el cambio.
  4. Atiende los comentarios con nuevos commits en la misma rama.
  5. Cuando lo aprueben, pulsa Merge y actualiza tu copia local con git pull.

Si quieres contribuir a un proyecto ajeno, primero haz un fork (tu propia copia en GitHub) y abre el PR desde ahí.

Deshacer cambios

Elige el comando según lo que quieras revertir:

git restore archivo.txt            # descarta cambios sin preparar
git restore --staged archivo.txt   # saca un archivo del staging
git commit --amend -m "Nuevo mensaje"   # corrige el último commit
git revert abc1234                 # crea un commit que anula otro
git reset --hard abc1234           # vuelve atrás y BORRA cambios

Evita reset --hard y push --force en ramas compartidas: pueden borrar trabajo de otras personas. Para historia ya publicada, usa revert.

Archivos ignorados

Crea un archivo .gitignore en la raíz para que Git no registre archivos generados o secretos.

node_modules/
.env
*.log
.DS_Store
dist/

Nunca subas contraseñas ni claves. Si ocurre, cámbialas de inmediato: borrar el archivo después no elimina la historia.

Buenas prácticas

  • Haz commits pequeños que hagan una sola cosa.
  • Trabaja en una rama por cada tarea y deja main estable.
  • Ejecuta git pull antes de empezar a trabajar.
  • Revisa con git status y git diff antes de hacer commit.
  • Escribe un README.md que explique qué hace el proyecto y cómo usarlo.
